# FINORA — Personal Finance Manager

Responsive web app starter for individual personal-finance tracking. Includes a blush-pink premium UI, dashboard, transaction entry, category budgets, savings goals, debt tracking, investment ledger, financial insights, multi-currency display, theme selection, and PDF export with preset/custom paper dimensions.

## Important status

This is a working frontend starter, not a hosted production service. Real individual accounts and persistent cross-device data require a Supabase project and deployment. Without Supabase credentials, the app opens in **preview mode** with sample data; that mode is not secure account storage and changes are kept only in the current browser session.

## Run locally

1. Install Node.js 20+.
2. In this folder run `npm install`.
3. Copy `.env.example` to `.env` and fill in your Supabase project URL and anon key.
4. In Supabase SQL Editor, run `supabase/schema.sql`.
5. In Supabase Authentication settings, enable Email provider and configure the allowed site/redirect URLs for your local and deployed domains.
6. Run `npm run dev` and open the local URL printed by Vite.
7. Run `npm run build` to create the production bundle in `dist/`.

## Security model

- Supabase Auth handles registration, login, and sessions.
- Each private table has Row Level Security enabled.
- Policies require `user_id = auth.uid()` (profiles use `id = auth.uid()`).
- Never put a Supabase service-role key in this frontend. Use only the anon/public key.
- Configure email confirmation, strong password policy, backups, and HTTPS before real use.

## Features and current implementation notes

- Dashboard summaries, six-month cash-flow chart, category pie chart, latest transactions.
- Transaction create/delete; Supabase persistence for transactions when configured.
- Budget, goals, debts, and investments are currently UI/session state. The schema is ready for persistence, but CRUD wiring for these modules is the next implementation milestone.
- Currency selector changes display formatting; it does not convert exchange rates. Each transaction should be stored with its original currency before enabling true multi-currency consolidation.
- PDF exports use jsPDF and support A4, A5, A6, Letter, Legal, and custom dimensions in millimeters. The report currently contains a summary, category totals, and transaction rows; chart image embedding is a follow-up enhancement.
- Financial insights are deterministic rules based on recorded data, not a personalized licensed financial adviser or investment recommendation.
- Theme selection currently applies to the active app session; profile preference persistence is a follow-up task.

## Suggested production milestones

1. Wire CRUD and ownership for budgets, goals, debts, investments, and preferences.
2. Add original-currency transaction fields and a dated FX-rate table/provider before combining currencies.
3. Add automated tests, audit logging, export privacy review, error monitoring, and database backups.
4. Deploy the Vite build to a static host (e.g. Vercel/Netlify) and configure Supabase redirect URLs and custom domain.

## Language and deployment

- Language selector: Bahasa Indonesia (`id`) and English (`en`), available in the top bar and settings. The current release localizes the main navigation, dashboard headline/cards, report headings, and core settings; some detailed form copy, advisor explanations, and PDF labels remain Indonesian and should be completed before broad public launch.
- Language preference is saved in the current browser. Currency display formatting follows the selected language, but currency conversion is not performed.
- Deployment presets are included for Vercel (`vercel.json`) and Netlify (`netlify.toml`). Both use SPA rewrites so refreshing an app route returns to `index.html`.

### Publish a public URL

1. Create a private GitHub repository and upload the contents of this folder (do not upload `.env`).
2. Import the repository into Vercel or Netlify.
3. Set build command to `npm run build` and output directory to `dist` (Netlify is preconfigured; Vercel detects Vite automatically).
4. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in the host's environment variables.
5. Deploy, then add the resulting public domain to Supabase Authentication > URL Configuration > Site URL and Redirect URLs.
6. Run `supabase/schema.sql` in the Supabase SQL Editor before allowing real accounts to use the app.

The public website URL is generated by the hosting provider after deployment. This source archive itself is not a live website and does not create a public URL until the hosting and Supabase configuration steps are completed.
